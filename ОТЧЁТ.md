# Отчёт по лабораторно-практической работе № 4
## Тема: Работа с ветками в Git

### Цель работы
Научиться создавать ветки Git, переключаться между ними, выполнять слияние и разрешать конфликты.

### Выполненные действия
1. Создан локальный репозиторий `my-branching-repo` с основной веткой `master`.
2. Создан файл `README.md` и выполнен первоначальный коммит `Initial commit`.
3. Создана ветка `feature-a`; добавлен `feature-a.txt`, выполнен коммит `Added feature-a.txt`.
4. Создана ветка `feature-b`; добавлен `feature-b.txt`, выполнен коммит `Added feature-b.txt`.
5. Ветка `feature-a` слита в `master`, затем в `master` слита ветка `feature-b`.
6. Для демонстрации конфликта файл `feature-a.txt` был изменён отдельно в `feature-a` и `master`.
7. При повторном слиянии Git обнаружил конфликт. Конфликт разрешён вручную: в файле сохранены обе строки — `Conflict line from feature-a` и `Conflict line from master`.
8. Выполнен коммит `Resolved conflict in feature-a.txt`.
9. После слияния удалены локальные ветки `feature-a` и `feature-b`.
10. Проверены состояние репозитория и граф истории коммитов.

### Основные использованные команды
```bash
git init -b master
git checkout -b feature-a
git checkout master
git checkout -b feature-b
git merge feature-a
git merge feature-b
git log --oneline --graph
git merge feature-a
git add feature-a.txt
git commit -m "Resolved conflict in feature-a.txt"
git branch -d feature-a
git branch -d feature-b
git status
```

### Разрешение конфликта
В `feature-a.txt` оставлены обе версии строки, чтобы сохранить изменения из обеих веток:
- `Conflict line from feature-a`
- `Conflict line from master`

### Результат
Работа с ветками, слиянием и разрешением конфликта выполнена. Ветка `master` содержит итоговые файлы и коммит разрешения конфликта. Ветки `feature-a` и `feature-b` удалены после слияния.

### Примечание
Скриншоты не приложены: их можно сделать на своём компьютере, открыв репозиторий и выполнив команды `git log --oneline --graph` и `git status`. История коммитов уже сохранена в папке `.git`.
